## Подготовка

Не менять рабочую БД/корень и не останавливать SQL ради проверки. Для изолированной
приёмки — новая test БД и пустой отдельный корень по README. Для smoke существующей
установки — новая явно учебная личная папка, никакого удаления прежних документов.
Закрыть свои старые экземпляры после сохранения; собрать Release, записать commit/дату.
Настройки масштаба меняет пользователь. Размеры — DIP: 1024×640 и 1440×900;
при 150% физическое окно больше, убедиться в достаточном разрешении экрана.

## Чистая установка — 10.06

1. Новый Windows-профиль/VM/ПК, без старых SFM_* переменных, конфигов и Storage.
2. Записать версии Windows/SDK/Desktop Runtime/SQL и способ TLS-доверия.
3. Получить исходники, выполнить README шаги restore/build/tool/migrations на **новой БД**.
4. Задать новый абсолютный локальный StorageRoot, доступный этому Windows-пользователю.
5. Publish в пустой каталог; передать всю папку на новую установку. Проверить, что нет
   исходников/Development JSON/Storage/тестовых БД в поставке.
6. Запустить из другого рабочего каталога с абсолютным SFM_CONFIG_DIRECTORY.
   Зарегистрировать первого пользователя, выполнить M01–M09 и перезапуск с тем же GUID.
7. В отдельном test config выбрать отсутствующую БД: убедиться в безопасном отказе,
   отсутствии авто-миграции/seed; вернуть конфиг и проверить Retry.
8. Сохранить actual/status, версии, screenshots и команды. Чужие данные не очищать.

Статус clean install: **NOT RUN**, чистая среда не предоставлена.
Частичный smoke публикации на машине разработчика — TEST_REPORT; это не clean install.
