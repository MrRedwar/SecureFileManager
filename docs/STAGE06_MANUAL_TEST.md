## Подготовка

Закрыть старый экземпляр приложения (сохранить нужные изменения), остановить отладку VS.
Открыть SecureFileManager.sln в VS 2022, Debug, профиль SecureFileManager (Development), F5.
Не менять локальный appsettings.Development.json: текущие SQL Server/SecureFileManagerDB,
Windows Authentication/TLS и StorageRoot на D: остаются прежними. Миграций этапа 06 нет.
Запуск из CLI: `dotnet run --project src/SecureFileManager.Wpf --launch-profile "SecureFileManager (Development)"`.

Работать только с новой папкой `stage06-check` своего пользователя и копиями примеров из
`docs/test-data/stage06`. Это явно тестовые документы, не seed для рабочего хранилища.
Не использовать ценные документы. Внешние примеры импортировать кнопкой «Импортировать»;
не открывать произвольные пути в редакторе. Для больших/XXE примеров не использовать личные данные.

## Общий редактор, конфликт и регрессия

| Действие | Ожидаемый результат |
|---|---|
| В «JSON / XML» пройти в stage06-check, выбрать JSON/XML и открыть | Используются личные папки, показаны каталоги/JSON/XML; TXT скрыт фильтром. Это тот же редактор и файловый сервис |
| Повторно открыть тот же документ из другого раздела | Активируется существующее окно, второй независимый буфер не создаётся |
| В открытом тестовом документе сделать правки; изменить его на диске Блокнотом и сохранить снаружи; попытаться сохранить в приложении | Конфликт, внешние байты не перезаписаны, несохранённый буфер остаётся |
| «Перечитать», сначала отказаться, затем подтвердить | Отказ сохраняет буфер; подтверждение заменяет его версией диска только после успешного чтения/аудита. При ошибке буфер остаётся |
| Перейти между разделами при открытом редакторе | Окно/правки остаются; закрытие приложения/выход проходят через подтверждение |
| «Диски», обновить; навигация/создание папки/TXT/импорт/поиск/сортировка; удалить только ненужную тестовую копию | Ранее принятые функции работают, удаление требует подтверждения; данные/история согласованы |
| 1024×640, Windows 100%/150%, редактор 600×440; Tab, Enter, Ctrl+S, Alt+F4 | Читаемый песочный редактор, команды/сообщения доступны, нет перекрытий; длинные имя/ошибка не ломают окно |

Не останавливать рабочий SQL Server, не заполнять диск и не менять ACL ради теста.
SQL/IO failures, компенсация, traversal, links, чужие ID и смена сессии покрыты изолированными тестами.
Фактическое disk-full/power loss и отдельная file symlink остаются специальными непроведёнными проверками.

## SQL (только чтение, без секретов)

Указать свой существующий GUID. Ограниченная выборка не выводит пароли/хеши/содержимое.

```sql
DECLARE @Owner uniqueidentifier = '00000000-0000-0000-0000-000000000000'; -- заменить своим GUID
SELECT Id, Name, SizeBytes, ModifiedAtUtc, IsDeleted
FROM Files WHERE OwnerId = @Owner AND RelativePath LIKE N'stage06-check/%';
SELECT TOP (100) OccurredAtUtc, OperationType, Result, FileId, Details, CorrelationId
FROM Operations WHERE UserId = @Owner ORDER BY OccurredAtUtc DESC;
```
