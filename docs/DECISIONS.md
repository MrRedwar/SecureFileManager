## 2026-11-01 — Этап 02: модели и Persistence

Пользователь явно разрешил этап 02. До миграции дважды подтверждено отсутствие
SecureFileManagerDB на .\SQLEXPRESS; создана только новая база, без seed и без
изменения существующих баз. Новая initial migration — 20261101094955_InitialCreate.

Идентификаторы всех моделей — Guid; ссылки nullable там, где требует ТЗ.
Username/RelativePath используют Latin1_General_100_CI_AS (без учёта регистра,
с учётом диакритики). Путь метаданных канонический относительный с разделителем `/`.
Максимумы: имя файла 255, относительный путь/снимок 400, расширение 32,
PasswordHash 1024, Details 512, ActorNameSnapshot 50. Путь 400 оставляет составной
уникальный индекс в пределах 900 байт. Политика ограничивает длину метаданных;
поддержка иных длин требует отдельного решения/миграции, не скрытого обрезания.

Soft-delete: глобальный фильтр !IsDeleted; уникален только активный (OwnerId,RelativePath).
IsDeleted согласован с DeletedAtUtc SQL CHECK. Все три FK NO ACTION: каскадного
удаления истории нет. DbContext.Remove(FileRecord) преобразуется в soft-delete;
Operations append-only через контекст, Users не удаляются. RowVersion добавлен
как технический токен конкурентного изменения Files. В репозиториях он обязателен
для update/delete и не подменяет проверки владельца/путей будущего сервиса.

DateTime принимаются только UTC; чтение datetime2 восстанавливает Kind=Utc.
Enum сохраняются строками с CHECK; все 14 типов событий ТЗ присутствуют.
Результаты репозиториев типизированные, без сырых исключений/конфигурации/хешей.
Методы создают отдельный DbContext. Общая транзакция файловой системы, метаданных
и аудита не обещается; это работа сервисов этапа 05. Репозитории не выполняют
регистрацию, хеширование, аутентификацию или физические файловые операции.

Добавлен только Microsoft.EntityFrameworkCore.Design 9.0.22 (PrivateAssets=all)
для дизайна миграций и локальный dotnet-ef 9.0.22 в .config/dotnet-tools.json.
Provider/EF/Relational/Design имеют одну версию; Core новых пакетов не получает.
Design-time factory находится в Data; Data также startup-проект EF CLI,
для него включён GenerateRuntimeConfigurationFiles. Wpf не получает Design-пакет.

Конфигурация загружается Data (System.Text.Json, без дополнительного конфиг-фреймворка).
SFM_ENVIRONMENT по умолчанию Production; SFM_CONNECTION_STRING из среды имеет приоритет,
иначе загружается файл appsettings.json из SFM_CONFIG_DIRECTORY/каталога приложения.
Только явный Development выбирает appsettings.Development.json. Encrypt=False запрещён;
TrustServerCertificate=True запрещён в Production и на нелокальном/не-SQLEXPRESS адресе.
Системные базы запрещены как целевой каталог приложения. DI-регистрация и design-time
factory используют один загрузчик. Runtime автоматически БД не создаёт и не мигрирует.
Невалидная конфигурация при старте обрабатывается безопасным стандартным сообщением.

Найденный уже отслеживаемый appsettings.Development.local.json содержал Windows
Authentication без паролей, но нарушал намерение хранить исключение только локально.
Файл удалён из дерева; настройки перенесены в игнорируемый appsettings.Development.json,
исключённый из MSBuild items. Добавлены правила для обоих вариантов локальных имён.
Общий пример по-прежнему TrustServerCertificate=False. Git-история не переписывалась,
индекс не изменялся вручную и commit не создавался.

SQL-тесты включаются только явным SFM_RUN_SQL_TESTS=1. Создают новую БД с уникальным GUID,
