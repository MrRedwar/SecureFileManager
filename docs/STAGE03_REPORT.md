# Этап 03 — Тематический WPF-каркас и навигация

Дата: 01.11.2026. Статус: **Частично по приёмке** — реализация и автоматические
проверки завершены, ручная проверка 03.06 остаётся открытой.

## Представления и работающие элементы

| Экран | Реализация |
|---|---|
| Мои файлы | Путь с честным состоянием входа, четыре отключённые команды, поле поиска, нативный DataGrid с четырьмя колонками, готовый шаблон иконок строк, выбор и счётчик отображаемых элементов, пустое/loading/error состояния |
| Диски | Карточка будущего накопителя с явно отсутствующими данными объёма/ФС и неопределённым заполнением, объяснение режима только чтения; DriveInfo не вызывается |
| Архивы | Нативная таблица, отключённые создание/просмотр/распаковка, проектные лимиты ZIP, пустое состояние |
| JSON / XML | Область выбора документа, отключённые команды, пустая readonly текстовая область, строка состояния и общий шаблон ошибок |
| Журнал | Таблица даты/пользователя/операции/объекта/результата, отключённые фильтры, легенда успешного/отклонённого/ошибочного события; записей БД не выдаётся |
| Настройки | Реальная версия сборки; «Не авторизован»; рабочая область недоступна; БД не проверена в текущем запуске; перечисление политики безопасности без утверждения её полной реализации |

Навигация меняет SelectedSection и соответствующее представление внутри одного
ContentControl. Отдельные singleton ViewModels зарегистрированы в существующем DI.
ListBox SelectedItem синхронизируется с VM; NavigateCommand проверяет допустимую
цель. Состояние каждого раздела сохраняется при переключении.

У окна WindowChrome: нативные области перетаскивания/resize, CaptionHeight=104,
ResizeBorderThickness=6, команды SystemCommands для сворачивания, maximize/restore
и закрытия. В code-behind только это платформенное UI-поведение и InitializeComponent.
Нативная интерактивность оконного менеджера пока требует ручного подтверждения.

Не реализованы и не маскируются готовыми: вход, файловые CRUD, поиск по диску,
редактирование форматов, ZIP, загрузка журнала и runtime-диагностика БД.
Неиспользуемого переключателя «список/плитка» нет: второй вид пока отсутствует.
Числа внизу относятся к отображаемой коллекции, не к физическому Storage.

## Ресурсы и стили

Подключены Colors, Icons, Brushes, Typography, Controls, DataGrid, Navigation,
Converters, States, Views. Палитра соответствует всем 15 токенам DESIGN_SPEC.
Стили охватывают Button/PrimaryButton/CaptionButton, TextBox, ComboBox, DataGrid
и его строки/ячейки/заголовки, NavigationItem, ScrollBar, CheckBox, DialogWindow,
Card и StatusBadge. Есть Hover/Pressed/Selected/Disabled/Focus.
ComboBox и ScrollBar сохраняют нативные шаблоны и поведение WPF.
DialogWindow — готовый ресурс, бизнес-диалоги будущих этапов не открываются.

18 PNG скопированы без изменения байтов в Wpf/Assets и встроены как Resource;
оригинальный лист и полный концепт не встроены. SourceRect/CroppedBitmap убирает
поля при отображении; исходная alpha сохраняется в оригиналах. Stretch=Uniform
для иллюстраций/иконок; UniformToFill только для фоновых текстур с малой opacity.
Происхождение/применение всех изображений — ASSETS.md.

## Визуальное сравнение с концептом — 03.07

Проверены рендеры всех экранов в обоих размерах, отдельно «Мои файлы» при 150%.
Совпадают: navy-шапка/sidebar, золото, логотип, подзаголовок, крылатое солнце,
шесть разделов с тематическими иконками, бирюзовый активный пункт, Анубис внизу,
папирусный фон, инструменты и таблица файлов, нижний орнамент.

Осознанные отличия:
- Нет вымышленных файлов и admin: отображается неавторизованное пустое состояние.
- Нет ложных «Журнал активен» и свободного объёма: карточки честно недоступны.
- Иллюстрации/иконки взяты из предоставленного комплекта; они объёмнее и подробнее
  плоских символов исходного концепта. Неподготовленные внешние картинки не добавлялись.
- Умеренные текстуры/тени, системные Segoe UI/Georgia, без пейзажа за окном.
- При 1024×640 поиск переходит на вторую строку, пустое состояние становится компактным,
  Анубис уменьшается; настройки прокручиваются. Декор не перекрывает controls.
- Текущая версия не предлагает плитку, пользовательский выход или файловые действия.

Обнаруженные ошибки исправлены: порядок загрузки ResourceKey (XamlParseException),
двойной отступ TextBox, применение базовых стилей к производным Window/UserControl,
устаревший перерасчёт колонок в первоначальном неподключённом тестовом дереве.
Последнее исправлено в тесте показом настоящего окна вне рабочего стола.
На финальном подключённом дереве колонки перерасчитываются нативно; отдельный
обработчик изменения колонок в продукт не вводился.

## Ручная приёмка 03.06

1. Закрыть тестовые экземпляры. Выполнить команды сборки выше, затем
   `dotnet run --project src/SecureFileManager.Wpf -c Debug --no-build`.
2. В настройках экрана Windows вручную установить масштаб 100%; перезапустить приложение.
   Проверить окно 1440×900 и 1024×640 **DIP**, сверяясь с приложенными рендерами.
3. Повторить при 150%, перезапустив приложение после смены масштаба.
   1440×900 DIP при 150% занимает 2160×1350 физических пикселей; нужен достаточный
   размер рабочего пространства монитора. Если экран меньше, отметить ограничение среды.
4. Мышью выбрать по очереди все шесть разделов: меняются экран, заголовок и выделение,
   новое главное окно не появляется. Проверить Hover, tooltip недоступных действий,
   прокрутку настроек и таблиц; ни одна disabled-команда не выполняет операцию.

   по шапке; проверить Свернуть и восстановление через панель задач,
