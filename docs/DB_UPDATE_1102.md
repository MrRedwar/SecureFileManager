# Обновление рабочей БД для этапа 11.02

Дата: 07.11.2026. Пользователь прямо поручил завершить обновление рабочей БД.
Target проверен по фактическому Development-конфигу приложения: локальный
`.\SQLEXPRESS`, `SecureFileManagerDB`, Windows Authentication; TLS включён.
Локальное Development-исключение доверия сертификату осталось прежним.

## Результат

**Миграция `20261107101211_AddExternalDocuments` применена и зафиксирована.**
История содержит три миграции, ожидающих миграций нет. Новая ExternalDocuments,
два nullable столбца внешнего аудита, unique PathKey index и FK NO ACTION доступны;
FK включён и trusted. Проверка готовности БД через настоящий DI приложения вернула true.

| Таблица | До | После | Сохранность прежних данных |
|---|---:|---:|---|
| Users | 2 | 2 | полное прежнее содержимое совпало |
| Files | 9 | 9 | полное прежнее содержимое совпало, включая RowVersion |
| Operations | 136 | 136 | все прежние столбцы/строки совпали |
| ExternalDocuments | отсутствовала | 0 | новая пустая таблица, без seed |

Сверка выполнялась не только по количеству: перед DDL взяты TABLOCKX/HOLDLOCK на
Users/Files/Operations, серверные SHA-256 упорядоченных JSON-представлений всех прежних
данных сравнивались перед COMMIT внешней транзакции. При несовпадении предусмотрены
THROW/XACT_ABORT и откат. Пароли, password hashes, документы и сами контрольные суммы
не выводились и не сохранялись в клиентский отчёт. Id/хеши/содержимое старых данных
не переписывались. Пользовательский Storage и реальные файлы не затрагивались.

## Применение и проверка EF

Применён ранее сгенерированный/проверенный idempotent EF SQL от второй миграции к
третьей. Скрипт помещён во внешнюю транзакцию с проверкой baseline (две старые миграции,
новые объекты отсутствуют), сверкой данных и новой схемы до COMMIT. Ни DROP/DELETE/
UPDATE прежних данных, ни Down не выполнялись. История обновлена стандартной записью
EF migration/ProductVersion9.0.22. Startup приложения по-прежнему не применяет миграции.

После COMMIT выполнен отдельный реальный EF-прогон через `App.CreateServices`:

- DatabaseConnectionCheck.CanConnectAsync: true.
- GetAppliedMigrations:3; GetPendingMigrations:0.
- AppDbContext вставил ExternalDocument, получил RowVersion, вставил Operations с
  внешним FK/path; FK и mapping прошли проверку.
- Эти пробные вставки выполнены внутри обязательного RollbackAsync. После отката
  повторно проверено отсутствие probe ID в обеих таблицах и совпадение всех counts.
- Настоящие пользовательские файлы и содержимое Storage не открывались/не изменялись;
  путь rollback-probe был только метаданными внутри откатившейся SQL-транзакции.

Финальный read-only SQL подтвердил три миграции, counts2/9/136/0, trusted FK и
encrypt_option=TRUE. Производственный код этой задачей не менялся; ранее проведённые
175/175 тестов повторно не запускались без необходимости. Это реальная проверка
рабочего подключения/EF, не native GUI-приёмка редактора.

Технические артефакты (ignored, без дампов строк/секретов):
