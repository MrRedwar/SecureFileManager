## Подготовка

Открыть существующее решение в VS 2022, Debug/net9.0-windows, выбрать
SecureFileManager (Development). Остановить старый exe перед пересборкой.
Проверить игнорируемый appsettings.Development.json: StorageRoot указывает на
D:/SecureFileManagerData/Storage, SQL использует прежнюю базу/Windows Authentication/TLS.
Пустой/устаревший override SFM_STORAGE_ROOT не должен указывать на старое место.
Ничего не переносить и не пересоздавать, миграции этапа 05 отсутствуют.

Тестировать только файлы с префиксом stage05-check в специально созданной пустой
папке. Не выбирать ценные документы для удаления. Создать отдельный безвредный
внешний TXT со строкой «Источник для проверки импорта»; сохранить его исходную копию.

## Отказы и восстановление — только изолированная среда

SQL/IO failures, concurrent create, foreign ID, missing SQL, junction/hard link,
старая версия, прерванная публикация и ambiguous commit уже проверены автоматически.
Не отключать реальный D, не заполнять диск, не менять ACL и не редактировать рабочую
служебную папку ради теста.

Если приложение само сообщает pending: сначала восстановить доступ к тому же диску/SQL,
затем «Восстановить». Успешный SQL CorrelationId завершит очистку; неподтверждённый
откатит подготовку без перезаписи внешних изменений. Если ошибка остаётся, сохранить
резервную копию каталога и plan/old, обратиться к FILE_OPERATIONS.md; не удалять их вручную.

Отдельная символическая ссылка, физический disk-full и настоящий power loss остаются
непроверенными в live среде. Для symlink нужен заранее разрешённый отдельный тестовый
Windows-профиль/каталог; не менять системные настройки безопасности ради приёмки.

## Автоматический повтор с уборкой

Из PowerShell в корне:

```powershell
dotnet restore
dotnet build SecureFileManager.sln -c Debug
.\scripts\Test-Stage05.ps1 -TestParent 'D:\SecureFileManagerData\Stage05Tests'
```

Скрипт создаёт новый run-GUID вне Storage/Git, запускает все тесты с реальным SQL.
Fixture удаляет только новую БД этого запуска; скрипт удаляет только свой каталог,
не следуя junction/symlink. Старые базы/директории при SFM_EXISTING_TEST_DATABASE
не удаляются. Без SFM_RUN_SQL_TESTS=1 обычный dotnet test пропускает SQL — это не полная приёмка.

Записать фактический результат в PROGRESS и завершить открытую GUI-проверку 05.09.
Этап 06 и Git-коммит требуют отдельного разрешения.
