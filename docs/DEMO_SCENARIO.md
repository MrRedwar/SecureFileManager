# Сценарий защиты — 12 действий

Ориентир: 8–12 минут. Это инструкция; **сам сценарий финального показа NOT RUN**.
Подготовить Windows/SQL и конфиг по README, выполнить автоматический прогон заранее.
Использовать отдельную учебную БД и новый пустой StorageRoot с согласованным конфигом
или только новую личную demo-папку; рабочую БД не пересоздавать/не очищать.
Выбрать свободное имя `defense-20261103-<суффикс>`, не перезаписывать существующее.
Логин/пароль вводит демонстратор; не включать их в экранную запись/отчёт.
После установки нельзя переключать Storage отдельно от связанной БД и GUID пользователей.

| № | Что нажать / выполнить | Что показать и объяснить | Ожидаемый результат |
|---|---|---|---|
| 1 | Запустить Wpf по README | Окно входа, фактическая проверка SQL; миграций на старте нет | Без главного окна до входа; понятный результат проверки подключения |
| 2 | Зарегистрировать новый demo-аккаунт на новой установке или войти существующим | Пароль скрыт, в SQL хеш с солью; GUID личного корня, session/owner | Главная область с текущим логином; секреты не показываются |
| 3 | «Диски» → «Обновить» | Настоящие объём/ФС/готовность, read-only граница | Сведения накопителей; нет выбора произвольного диска для записи |
| 4 | «Мои файлы» → «Создать папку», имя defense-...; открыть | Свой относительный путь, SQL Files, отсутствие фиктивных рабочих файлов | Новая папка в личной области |
| 5 | «Создать файл» → note.txt → открыть → ввести строку из demo/example.txt → Ctrl+S | Dirty indicator до commit, UTF-8, после сохранения размер/дата | Сохранённый текст повторно читается; FILE_CREATED/FILE_UPDATED |
| 6 | Создать note.json, вставить demo/example.json, «Проверить» → сохранить | System.Text.Json; затем временно убрать скобку и «Проверить» | Валидный JSON принят; неверный не сохранён. Вернуть корректный текст перед закрытием |
| 7 | Создать note.xml, вставить demo/example.xml, «Проверить» → сохранить | XmlReader, запрет DTD/внешних сущностей | Валидный XML сохраняется; структура/русский текст читаются |
| 8 | «Импортировать» → выбрать demo/example.txt | Копирование одного внешнего источника, не перенос и не внешний root | Файл в текущей папке, исходник demo остаётся прежним |
| 9 | Ctrl/Shift выбрать note.txt/note.json/note.xml → «Архивировать», имя defense.zip в текущей папке | Store ZIP, ограничения и отсутствие self-inclusion; дождаться результата | ZIP появился после Files+audit commit; исходники сохранены |
| 10 | «Архивы» → defense.zip → «Открыть архив» → «Распаковать»/«Далее», новая папка unpacked | Preview без извлечения, проверка перед публикацией целого дерева | Новая папка с совпадающими документами; нет merge/overwrite |
| 11 | «Журнал» → «Обновить», фильтры ZIP_CREATED/ZIP_EXTRACTED или поиск defense | Свой actor, статус, UTC в SQL/локальное отображение, история не редактируется; при необходимости SELECT из manual test | События соответствуют выполненным действиям, без содержимого/абсолютного источника |
| 12 | В demo-папку импортировать demo/forbidden-dtd.xml, попытаться открыть | Безвредный пример с внутренней entity, DTD полностью запрещён; показать отказ и журнал. Затем выйти | Отказ без внешнего IO; приложение отвечает, LOGOUT либо честное сообщение об ошибке аудита |

Альтернатива шага 12: в диалоге создания указать `../escape.txt`; ожидать отказ без
создания файла. Настоящие bombs, заполнение диска и остановка рабочего SQL не нужны.
Новые данные показа не удаляются автоматически. Не трогать `.sfm-internal`.
При RecoveryRequired прекратить показ файловых действий, сохранить состояние и следовать
FILE_OPERATIONS; не удалять планы ради демонстрации. Перед защитой собрать настоящие
снимки по SCREENSHOT_CHECKLIST и записать реальные результаты ручного прогона.
