## Подготовка

Закрыть старый экземпляр приложения с сохранением нужных правок. В VS 2022 открыть
SecureFileManager.sln, Debug, профиль SecureFileManager (Development), F5.
Либо из корня: `dotnet run --project src/SecureFileManager.Wpf --launch-profile "SecureFileManager (Development)"`.
Не менять StorageRoot/рабочую БД/миграции. Корень остаётся D:/SecureFileManagerData/Storage/Users/{UserId}.

Использовать только новую личную папку `stage07-check` и явно тестовые документы.
ZIP создаётся как Store (без сжатия): такой ZIP совместим с защитой 100:1 даже для повторяющегося текста.
Распаковка создаёт **новую именованную папку** в выбранном родительском каталоге.
Существующие папки не объединяются и файлы не перезаписываются.

## Раздел «Архивы», отмена и регрессия

| Действие | Ожидаемый результат |
|---|---|
| Открыть «Архивы», вкладку «ZIP-архивы» | В текущей личной папке показаны ZIP и каталоги для навигации, поиск/сортировка/размер/дата работают |
| Вкладка «Создать архив: выбрать файлы», выбрать объекты, «Архивировать» | Тот же сценарий, сервис и правила назначения, что в «Мои файлы» |
| Открыть вложенную папку Enter/двойным щелчком в выборе назначения; «Вверх»/«К корню» | Меняется только личный относительный путь, выбрать произвольный OS-путь невозможно |
| Выбрать пустую папку как источник ZIP | В ZIP есть запись каталога; после извлечения папка существует |
| Выбрать папку и попытаться создать ZIP внутри неё | Отказ self-inclusion; нет окончательного ZIP и повреждения исходников |
| Во время подготовки нажать «Отменить ZIP» | Подготовка отменяется, текущие служебные результаты очищаются; старые данные целы. Если commit уже подтверждён, возможен успех; отмена не уничтожает committed результат |
| Во время операции перейти в другой раздел и вернуться | UI отвечает; статус соответствует фактическому результату; нет ложного Success во время подготовки |
| Повторить TXT Save, JSON/XML validation, импорт, поиск, сортировку, просмотр дисков | Функции 01–06 сохранены |
| Окно 1024×640 и 1440×900, Windows 100%/150%; Tab/Enter/Esc, Ctrl/Shift | Список и команды доступны, сообщения читаемы; диалоги помещаются; фокус работает |

Отмена проверяется на тестовых данных разумного размера, без настоящих ZIP Bomb.
Короткая операция может завершиться раньше нажатия — это не отрицательный результат теста отмены.
Некоторые фазы проверки handle/hash и обязательного завершения/компенсации не прерываются мгновенно.

## Безопасные негативные примеры

`docs/test-data/stage07` содержит маленькие специально созданные примеры.
Импортировать **копии** через приложение в stage07-check, не распаковывать опасные примеры сторонними программами.

| Сценарий | Ожидаемый результат |
|---|---|
| Открыть corrupt.zip | «ZIP повреждён», приложение работает, выходных файлов нет |
| Открыть unsafe-path.zip, попытаться распаковать | Предпросмотр предупреждает об опасном пути, «Далее» недоступно, нет файла stage07-outside.txt вне новой папки |
| Открыть duplicate.zip | Предупреждение о дубликате с учётом регистра, распаковка целиком запрещена |
| Создать второй backup.zip в том же месте | Конфликт без перезаписи первого ZIP |
| Распаковать повторно в существующий result | Конфликт, существующие файлы побайтно целы |
| Попытка назначения вне личного корня | UI не предоставляет такого выбора; сервисные absolute/traversal/чужие ID проверены автотестами |
| ZIP с запрещённой ссылкой, junction-назначение, заблокированный источник | Автотесты используют изолированные sentinel/junction/locked handle, доступ не расширяется |
| Лимиты 250 / 25 МиБ / 100 МиБ / 100:1 и поддельные размеры | Запустить ZipEngineTests и DeclaredLimitsAndCrcMismatchLeaveNoFinalTree: малые лимиты/данные, отказ и очистка; диск не заполняется |
| Недоступный SQL, отказ аудита, IO/disk-full | Запустить MissingSqlCannotCreateOrExtractArchive, ExtractAuditFailureRollsBackAllMetadataAndPublishedTree, SimulatedDiskFullAfterPublishCompensatesArchiveAndPreservesSources: нет ложного успеха и повреждения данных |

Не останавливать рабочий SQL Server, не заполнять накопитель, не менять ACL/права Windows ради проверки.
Физический disk-full/power loss и отдельная file symlink не заявляются выполненными; используются безопасные
контролируемые отказы, реальная junction и запрет reparse-флагов. Не удалять рабочие файлы/БД/служебные журналы.

## SQL — только чтение

Указать GUID своего существующего пользователя; не выбирать PasswordHash/пароли/содержимое.

```sql
DECLARE @Owner uniqueidentifier = '00000000-0000-0000-0000-000000000000'; -- заменить своим GUID
SELECT Id, RelativePath, Kind, SizeBytes, ModifiedAtUtc, IsDeleted
FROM Files WHERE OwnerId = @Owner AND RelativePath LIKE N'stage07-check/%';
SELECT TOP (100) OccurredAtUtc, OperationType, Result, FileId, Details, CorrelationId
FROM Operations WHERE UserId = @Owner ORDER BY OccurredAtUtc DESC;
```

Если возникло RecoveryRequired, сохранить данные и восстановить доступ к тому же SQL/диску,
затем «Восстановить». Не удалять .sfm-internal. Неожиданно изменённое дерево автоматически
не удаляется: нужен разбор по docs/FILE_OPERATIONS.md и STAGE07_REPORT.md.
