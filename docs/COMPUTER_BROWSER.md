## Как пользоваться

Войти → «Диски» → «Открыть диск» либо вкладка «Файлы компьютера».
Дважды щёлкнуть папку/диск или выбрать и нажать Enter/«Открыть папку».
Адресная строка принимает абсолютный локальный путь (например C:\Users), Enter/«Перейти».
Пустой адрес/«Этот компьютер» показывает диски, «Вверх» — родительскую папку,
«Обновить» перечитывает текущую. Поиск — имена среди загруженного списка;
сортировка — заголовки таблицы. Столбцы: имя, тип, размер, изменение, примечание.
При пустом/недоступном каталоге есть явный статус, при лимите10000 — предупреждение об усечении.

Внешние файлы не требуют регистрации/импорта в личную Files и не получают OwnerId
первого просмотревшего их пользователя. Под двумя app-логинами с одинаковым Windows
token видимость одинакова. Windows ACL не обходятся; app-пароль не предоставляет
другой Windows token. Нет обещания показать закрытые системой папки и чужие профили.
Личный Storage сохраняет изоляцию: его строка отмечена, переход через общий браузер
отклонён, включая junction. Для своих личных документов использовать «Мои файлы».
Нет сетевого обхода, рекурсии или автоматического чтения содержимого файлов.

## Реализация и безопасность

Core: ComputerEntry/ComputerDirectory/IComputerBrowseService/ComputerBrowseService;
IComputerDirectoryReader — узкий read-only инфраструктурный порт.
Wpf: WindowsComputerDirectoryReader использует существующий SafeNativeFile.Pin для
удержания физических предков, запрещает reparse chain/namespace обходы.
ComputerBrowserViewModel очищает адрес/фильтр/выбор/результаты при смене сессии,
отменяет запрос и отбрасывает поздний ответ по generation.
DrivesViewModel управляет двумя вкладками, не добавляя новый раздел приложения.
AsyncRelayCommand получил необязательную проверку параметра для кнопок конкретного диска;
старые двухаргументные вызовы сохраняют поведение.

Сервис требует active SQL User до чтения, проверяет session/revision до и после await.
Результат выдаётся после подтверждённого FILE_READ/COMPUTER_DIRECTORY_LISTED в Operations;
актёр/UTC реальны, FileId и TargetPathSnapshot NULL. В Details фиксированный код,
а не произвольные абсолютные пути/ошибки. Журнал отображает понятное описание.
При недоступной БД/аудите список не выдаётся. Метаданные внешних файлов не сохраняются
в личной Files, схема и рабочая БД не меняются. SQL/Windows-администратор вне модели угроз.
Browse — snapshot: он не доказывает право чтения/изменения байтов каждого файла.

## Короткая ручная приёмка (NOT RUN)

1. Войти A, открыть обычную внешнюю папку с небольшими существующими файлами.
2. Проверить имя/размер/дату, Enter/двойной щелчок по папке, вверх и адресную строку.
3. Проверить поиск и сортировку, пустую папку, безопасный отказ недоступного адреса.
4. Выйти → войти B → тот же внешний путь: состав общий, состояниеA не осталось.
5. Попытаться открыть настроенный StorageRoot через новый браузер: отказ;
   «Мои файлы» у каждого пользователя по-прежнему показывают только его данные.
6. Проверить журнал собственного пользователя, новые описания чтения каталога.
7. Проверить1024×640/1440×900, Windows100%/150%, Tab/Enter/видимый фокус.

Не менять рабочую БД/Storage/ACL, не удалять/перемещать реальные файлы для этой проверки.
