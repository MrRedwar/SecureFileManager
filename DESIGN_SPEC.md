# DESIGN_SPEC.md — Визуальная и UX-спецификация

Дополнение 07.11.2026: общий просмотр внешних папок размещается во второй вкладке
«Файлы компьютера» существующего раздела «Диски». Карточки накопителей получают кнопку
«Открыть диск». Сохраняются шесть разделов, navy/gold/papyrus и общие стили. Адресная строка,
Enter/двойной щелчок для папок, вверх/диски/refresh и поиск не должны закрывать таблицу
при 1024×640. Внешние изменяющие команды не показываются как готовые до их реализации.

**Проект:** Secure File Manager  
**Концепция:** «Храмовый архив» — мягкая древнеегипетская стилизация настольного WPF-приложения  
**Статус:** утверждённое направление + предложенные числовые параметры реализации  
**Визуальный референс:** [`design/egyptian-ui-concept.png`](design/egyptian-ui-concept.png)

> Референс — **изображение концепта**, а не готовая разметка. Нельзя вставлять его как фоновый скриншот вместо функциональных контролов. Реализовать нативные WPF-компоненты и стили с сохранением логики UX. Допустимы небольшие композиционные отступления ради удобства и адаптивности.

## 1. Принципы

1. **Современный менеджер файлов прежде всего:** визуальная иерархия, ясная навигация, компактные списки, предсказуемые действия.
2. **Египетская тема мягко:** насыщенный тёмно-синий/бирюзовый, песочный фон, золотые акценты, тонкая графика папируса/символов. Не делать тяжёлые каменные панели, рунические кнопки или нечитаемые заголовки.
3. **Поведение важнее декора:** действия расположены как в стандартном файловом менеджере, но оформлены индивидуально.
4. **Безопасность видима, но не навязчива:** состояние журнала, отказ в доступе, статус подключения — понятные короткие сообщения, а не драматические анимации.
5. **Текст на русском**; имена файлов/системные пути сохраняют оригинальные символы. Не переименовывать привычные функции («Удалить», «Открыть», «Сохранить») в мифологические термины.

## 2. Цветовые токены

| Токен WPF resource | HEX | Применение |
|---|---|---|
| `Color.Navy900` | `#192C36` | левая панель, верхняя панель, базовый тёмный |
| `Color.Navy800` | `#233944` | состояния hover на тёмном |
| `Color.Teal600` | `#177781` | основная кнопка, выбранный пункт, индикатор прогресса |
| `Color.Teal700` | `#115D67` | pressed/hover основной кнопки |
| `Color.Gold500` | `#BA8C45` | эмблема, разделители, декоративные акценты |
| `Color.Gold200` | `#E4D0AD` | светлые линии и рамки |
| `Color.Sand100` | `#F5F0E6` | панели/табличный фон |
| `Color.Paper50` | `#FBF9F5` | основная поверхность |
| `Color.TextPrimary` | `#1F2933` | обычный текст на светлом фоне |
| `Color.TextSecondary` | `#5D6267` | вспомогательный текст |
| `Color.TextOnDark` | `#F7F1E6` | текст боковой панели |
| `Color.Success` | `#287A50` | подтверждённый успех |
| `Color.Warning` | `#9A630B` | предупреждение |
| `Color.Danger` | `#AA3434` | ошибка и удаление |
| `Color.Border` | `#D7CCBC` | тонкие линии/границы |

**Правила:** золото применять как акцент и рамку, **не** как основной цвет мелкого текста на светлом фоне. Проверять контраст читаемого текста и иконок; для нормального текста стремиться к WCAG AA (4.5:1), для больших надписей/значимых иконок — 3:1. Цвет — не единственный признак успеха/ошибки. Не закладывать значения цветов в каждом XAML-контроле вручную: использовать `ResourceDictionary` и динамически заменяемые темы.

## 3. Типографика

- Основной текст и таблицы: **Segoe UI** (системный шрифт Windows), 13–14 px эквивалент WPF DIP; интерфейсные меню — 14–15.
- Заголовок основного раздела: **Georgia** или иной доступный системный serif, 26–30 DIP, средняя насыщенность.
- Название продукта в шапке: serif 22–25 DIP с умеренным межбуквенным расстоянием (если доступно без нестандартных зависимостей).
- Подписи/метаданные: Segoe UI 11–12 DIP; ошибки — не меньше 12.
- Не скачивать закрытые шрифты и не включать их в репозиторий без лицензии. WPF должен корректно подменять шрифт на системный.
- Основной текст не делать полностью прописными буквами; иероглифы только декоративные, не заменяют подписи действий.

## 4. Сетка, размеры и адаптивность

- Основная композиция: **верхняя шапка**, **боковая навигация слева**, **контент**, **нижняя панель статуса**.
- Базовый макет: 1440×900 DIP; начальное окно может быть 1360×820 DIP, располагаться по центру.
- Минимальные размеры главного окна: ориентировочно **1024×640 DIP**; элементы не должны перекрываться при уменьшении окна.
- Шапка: около 78 DIP; нижняя панель: 34–42 DIP; сайдбар: 230–250 DIP.
- Отступы: шкала 4/8/12/16/24/32 DIP. Радиусы: 4–8 DIP; карточки 8–12 DIP.
- Если ширина доступной области мала: прятать второстепенные колонки списка или включать горизонтальную прокрутку таблицы (не обрезать имена); панели кнопок могут переходить на две строки.
- Масштаб Windows: проверить 100%, 125%, 150%, 200%. Для WPF использовать layout-систему (`Grid`, `DockPanel`, `StackPanel`), а не фиксированные абсолютные координаты для основных элементов.

## 5. Карта экранов и детализация

### UI-01. Окно входа

**Композиция:** тёмный фон Navy900, ограниченная декоративная область с Оком Гора/тонкой золотой геометрией; светлая форма в центре шириной ~400–440 DIP.

**Элементы:** логотип; заголовок «Вход в хранилище»; поле «Логин»; `PasswordBox`; основная кнопка «Войти»; ссылка «Создать учётную запись»; ненавязчивый статус соединения.

**Поведение:** Enter запускает вход, если данные допустимы; поля с ошибкой имеют явную подсказку; пароль не отображается в логах; ошибка не раскрывает, существует ли логин. По успешном входе форма закрывается и открывается главная оболочка.

### UI-02. Регистрация

Поля: логин, пароль, повтор пароля; проверка обязательности, длины, совпадения паролей. Кнопки «Зарегистрироваться», «Назад ко входу». Сообщение об успехе — без раскрытия пароля. Ни регистрации, ни входу не нужна декоративная анимация.

### UI-03. Основное окно (по референсу)

**Верхняя панель:** слева эмблема Ока Гора (тематический символ), далее `SECURE FILE MANAGER`; справа стандартные оконные действия закрытия/сворачивания. Если реализуется безрамочное окно, сохранить системные сценарии перемещения, resize, Alt+F4, Win+стрелки и клавиатуру; в противном случае использовать стандартную рамку и тематическую внутреннюю шапку.

**Левая панель:** сверху список навигации с иконками; пункты **«Диски»**, **«Мои файлы»**, **«Архивы»**, **«JSON / XML»**, **«Журнал»**, **«Настройки»**; внизу текущий логин и «Выйти». Активный пункт выделяется бирюзовым прямоугольником и дополнительным контрастным маркером. Декор — в свободной нижней области, не под кнопками.

**Контент «Мои файлы»:** заголовок и путь («Моё хранилище / Документы»), карточки «Свободно на диске» и «Журнал активен» (строго по реальному состоянию), ряд действий «Создать», «Открыть», «Удалить», «Архивировать», поле поиска, переключатель вида при реализации двух видов. Ни одна кнопка не должна быть декоративной/пустой.

**Список файлов:** `DataGrid` с колонками «Имя», «Тип», «Размер», «Дата изменения»; у строк — иконка формата; пустой список имеет осмысленную подсказку и кнопку создания. Поддержать одиночный выбор, мультивыбор для архивации, двойной щелчок по папке/файлу. Удаление требует подтверждения. Колонки сортируются; дата локализована; tooltip показывает полное имя/метаданные при обрезке.

**Нижняя панель:** «Элементов: N · Выбрано: M», текущий пользователь/статус. Никаких статических подставных цифр. Девиз/орнамент допускается только в свободной области и не должен имитировать системные данные.

### UI-04. Диски

Карточки по дискам: буква, тип, ФС, свободный и общий объём, прогресс использования, `Недоступен` для неготового. Ясно указать: просмотр дисков **не означает** разрешение изменять всё содержимое. Отображать реальные данные из `DriveInfo`.

### UI-05. Редактор TXT / JSON / XML

Окно с заголовком имени файла и маркером `*` при изменении; основные команды «Сохранить», «Проверить формат» (JSON/XML), «Форматировать» (опционально), «Закрыть»; `TextBox` с многострочным редактированием и scrollbars, фиксированный/моноширинный шрифт в редакторе (Consolas/Cascadia Mono, если доступны). Строка статуса: формат, размер, наличие ошибок, состояние сохранения. Подсветка синтаксиса **не обязательна**. При закрытии с несохранёнными изменениями — «Сохранить / Не сохранять / Отмена».

### UI-06. Архивы

Панель списка ZIP, команды «Создать архив», «Просмотреть», «Распаковать»; диалог предварительного просмотра: имя записи, исходный размер, суммарные лимиты, замечания проверки. Во время операции — прогресс и, если реализована отмена, отдельная кнопка «Отменить». При опасном архиве — понятный отказ без извлечения файлов вне рабочей области. Не выводить «успех» до фактического завершения.

### UI-07. Журнал

`DataGrid`: «Дата и время», «Пользователь», «Действие», «Объект», «Результат». Над ним фильтры даты, действия и статуса, кнопка «Сбросить фильтры». Успех/отказ/ошибка различаются словами и значками, не только цветом. Открывать собственные события; пустая история показывает текст, а не фиктивные записи.

### UI-08. Настройки

Просмотр имени пользователя, относительного пути рабочего каталога, версии, установленного лимита редактора, ограничений ZIP, состояния БД; «Выйти». Не предоставлять кнопок, меняющих разрешённый физический корень на произвольный путь.

### UI-09. Диалоги

**Обязательные:** создание папки, создание файла, подтверждение удаления, подтверждение перезаписи (если позднее добавлена разрешённая перезапись), ошибка, предупреждение об опасном ZIP, сохранение изменений перед закрытием. **Формат:** короткий заголовок, причина простыми словами, основное действие справа/по стандарту платформы, явная «Отмена» для опасных действий. По умолчанию курсор не на destructive-действии.

## 6. Компоненты и состояния

| Компонент | Обычное | Hover/Focus | Disabled/Error |
|---|---|---|---|
| Primary Button | Teal600 + светлый текст | Teal700, видимая обводка фокуса | сниженная насыщенность, не только цвет |
| Secondary Button | Sand100 + Navy900 текст + Border | лёгкая золотая/бирюзовая рамка | не кликабельна, tooltip причины |
| Destructive Button | светлая с красной иконкой/текстом | явное выделение, подтверждение | не доступна без выбора |
| Navigation Item | тёмный фон, текст TextOnDark | тёмный teal hover | выбранный пункт имеет заполнение + маркер |
| Text Field | светлый фон + Border | заметная focus-border | ошибка: текст под полем, иконка, цвет |
| DataGrid row | Paper50/Sand100 по необходимости | лёгкая подсветка | выбранная строка — видимый focus/selection |
| Status | нейтральная метка | — | понятные `Успех`, `Отказано`, `Ошибка` |

**Анимации:** только короткие 120–180 мс для hover/появления небольших сообщений, при необходимости. Никаких анимированных пирамид/сцен и тяжёлых теней поверх таблиц.

## 7. Иконография и тематические иллюстрации

- Эмблема — стилизованное **Око Гора**. Меню «Диски» — диск/пирамида-геометрия; «Мои файлы» — понятная папка; «Архивы» — короб/запечатанный сундук; «JSON/XML» — `< / >`; «Журнал» — свиток; «Настройки» — анх + привычная шестерёнка.
- **Иконки не должны терять смысл.** Если иероглиф неочевиден, рядом обязательно текст.
- Желательно использовать масштабируемые WPF `Geometry`/`DrawingImage` либо корректно лицензированные/собственные векторные изображения. Не встраивать неизвестные внешние ресурсы с нарушением лицензий.
- Референсный фон с колоннами и пейзажем — контекст изображения-макета. В самом приложении использовать только ненавязчивые орнаменты по краям и, при желании, маленькую иллюстрацию снизу сайдбара; **не** делать обязательный полноэкранный пейзаж за формами.
- Ассеты лежат в `src/SecureFileManager.Wpf/Assets/`, с осмысленными именами. Происхождение собственных/сторонних ассетов фиксируется в `docs/ASSETS.md`.

## 8. Реализация в WPF

- Resource dictionaries: `Colors.xaml`, `Brushes.xaml`, `Typography.xaml`, `Controls.xaml`, `DataGrid.xaml`, `Icons.xaml`; подключать через `App.xaml`.
- Дизайн-токены извлекать в `StaticResource`/`DynamicResource`; избегать десятков уникальных цветов.
- MVVM: без обработчиков `Click` для бизнес-операций в code-behind; команды в ViewModel. Code-behind допустим для UI-поведения, которое не является бизнес-логикой.
- Иконки/картинки имеют alt-эквивалент через ToolTip/AutomationProperties.Name там, где сами по себе не подписаны.
- В формах сохранять корректный Tab-порядок, Enter/Escape, фокус после ошибки, стандартные сочетания Ctrl+S, Ctrl+F (по возможности), Del с подтверждением.
- Для `DataGrid` предусмотреть пустое состояние, загрузку/спиннер, ошибку, сортировку/выделение и скролл.

## 9. Критерии проверки визуала (UI-Acceptance)

- UI-01: главная панель действительно похожа на принципиальную компоновку референса, но **не является картинкой со спрятанными кнопками**.
- UI-02: все 6 пунктов навигации отображаются и открывают соответствующие разделы; статус логина корректен.
- UI-03: список реальных файлов (не хардкод) с колонками и рабочими действиями.
- UI-04: 1024×640 и 1440×900, 100% и 150% DPI без пересечений элементов и недоступных кнопок.
- UI-05: клавиатура достигает значимых действий, фокус заметен, сообщения об ошибках читаемы.
- UI-06: удаление и опасный ZIP требуют явного подтверждения/выдают видимый отказ.
- UI-07: при подключении к отключённой БД экран показывает ошибку, а не ложную зелёную отметку журнала.
- UI-08: при пустом каталоге не выводятся вымышленные `Отчёт.txt`, `backup.zip` и любые другие демонстрационные объекты, пока они реально не созданы.
- UI-09: единый стиль окон входа, регистрации, редактора, архивации, журнала и настроек.

## 11. Передача Codex

Перед реализацией экранов Codex должен прочитать `DESIGN_SPEC.md`, `TECHNICAL_SPEC.md`, открыть `design/egyptian-ui-concept.png` и отразить в результате: созданные стили/ресурсы, снимок окна после запуска, список работающих элементов и известные расхождения с макетом. Изменение палитры, схемы навигации и отказ от мягкой египетской тематики — только по прямому решению пользователя.
